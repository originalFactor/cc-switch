# 2.1 プロバイダーの追加

## 追加ページを開く

まずサイドバーで追加したいアプリを選び、ページヘッダー右側の **プロバイダーを追加** ボタン（+ 付き）をクリックします。

プロバイダーの追加で作れるのは **統合プロバイダー** だけです。1 つの設定を Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build で共有します。アプリごとのプリセット一覧も、アプリごとのカスタムフォームもありません。単一アプリのプロバイダーは一覧にある既存のもので、一覧から編集してください。

追加ページでフォームを操作した（文字入力、スイッチのオン/オフ、選択肢の変更）後に、サイドバー、トレイ、設定から現在のページを離れようとすると、先に「未保存の変更があります」の確認が表示されます。「破棄して移動」または「編集を続ける」を選べます。フッターの「キャンセル」をクリックした場合は、そのまま追加ページを閉じます。

## 統合プロバイダーの作成

1. 基本情報を入力します：
   - **名前**——左のアイコン枠をクリックするとアイコンを選べます（色はアイコンの既定色に従います）
   - **API エンドポイント**——ゲートウェイのベースアドレス。右の「管理・テスト」でアドレスの速度を測り、候補エンドポイントを追加できます
   - **API Key**
   - （オプション）**Web サイト URL** と **メモ**
2. 同期するアプリをオンにします。5 つのカードは初期状態ですべてオンで、オフにしたアプリには同期しません
3. 展開したカードにそのアプリ専用の項目を入力します。モデル設定はスイッチと一緒に同期されます
4. フッターの「追加」をクリックします

### アプリごとの専用項目

展開したカードには、モデルのほかにそのアプリ固有の詳細オプションと設定ファイルのスイッチが入ります：

| アプリ | 項目 |
|--------|------|
| Claude Code | メインモデルと Sonnet / Opus / Fable / Haiku の 4 段階ロールモデル、Subagent モデル、上流フォーマット（Anthropic / Chat / Responses / Gemini Native）、認証フィールド（`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY`）、カスタム User-Agent、上流互換スイッチ（Tool Search、Artifact ツール、auto mode のサーバー側チェック）。各段階の `/model` 表示名と 1M 対応の宣言は、選択したモデルのメタデータから自動生成されます |
| Claude Desktop | 接続方式（直結 / モデルマッピング）、マッピング時の上流フォーマット、ロール表（Sonnet / Opus / Fable / Haiku の 4 段階。各段階で実際のリクエストモデルを選択し、メニュー表示名は利用可能なモデル一覧での選択モデル名から自動生成されます）、直結時のモデルはプロバイダー単位の利用可能なモデル一覧から取得 |
| Codex | モデルと推論レベル、サブエージェントモデルとその推論レベル（このドロップダウンの選択肢も選択したモデルのメタデータに従います）、上流フォーマット（Responses / Chat / Anthropic Messages）、認証フィールド、圧縮しきい値（コンテキストウィンドウに対する割合。`config.toml` に書き込まれるトークン数は選択したモデルのウィンドウから計算されます）、リモート圧縮、Claude Code クライアントの模倣、完全 URL、カスタム User-Agent。モデルカタログは利用可能なモデル一覧から自動生成されます |
| Gemini CLI | モデル、`.env` と `settings.json` の 2 つの JSON ブロック（追加の環境変数と設定がこのアプリと一緒に切り替わります） |
| Grok Build | デフォルトモデル、上流プロトコル（Responses / Chat Completions / Anthropic Messages）。モデル一覧は利用可能なモデル一覧から自動生成され、モデルごとに 1 つの `[model."<id>"]` テーブルを書き、コンテキストウィンドウは各モデルのメタデータから取得します |

> 💡 Claude Desktop が受け付けるのは `claude-sonnet-*` / `claude-opus-*` / `claude-haiku-*` / `claude-fable-*` のロール ID です。プロバイダーがこれらの ID をそのまま受け付ける場合は **直結** を選ぶとモデル名が Desktop の設定にそのまま書き込まれます。DeepSeek や Kimi などそれ以外のモデル名は **モデルマッピング** を選び、ローカルルーターが 4 段階のロールを入力した実際のモデルに変換します。

> 💡 Grok Build は選択したプロトコルで直接接続し、モデル一覧は上の利用可能なモデル一覧から自動生成されます（モデルごとに 1 つの `[model."<id>"]` テーブルを作成し、アドレスとキーはこのプロバイダーのものを使用）。デフォルトモデルは `[models].default` がどのテーブルを指すかだけを決めます。Chat Completions または Anthropic Messages を選んだ場合は、Grok Build の[ローカルルーティング](../4-proxy/4.1-service.md)を有効にしてください。

> 💡 コンテキストウィンドウは手入力ではなくなりました：Codex の `model_context_window` は利用可能なモデル一覧にある選択中モデルのコンテキストウィンドウに従い、圧縮しきい値はそのウィンドウに対する割合です。`config.toml` に書き込まれる `model_auto_compact_token_limit` はそこから計算されます（1,000,000 のウィンドウで 90 なら 900000）。モデルにウィンドウのメタデータがない場合はどちらも書き込まず、Codex 自身の既定値に任せます。

> 💡 「リモート圧縮」は Codex のプロバイダーテーブルの `name` を `OpenAI` に書き、Codex にリモート圧縮を試させます。

> 💡 ここにあるのはプロバイダーと一緒に切り替わる項目だけです。グローバル設定ファイルに書かれ全プロバイダーに効くスイッチ（Claude Code の「AI 署名を隠す」「自動アップグレードを無効化」）は、単一プロバイダーの編集画面のままです。

### エンドポイントの速度テスト

**API エンドポイント** の右にある「管理・テスト」でゲートウェイのアドレスを測速し、候補エンドポイントを保存できます。パネルの説明は[エンドポイント速度テスト](#エンドポイント速度テスト)を参照してください。

統合プロバイダーのカスタムエンドポイント一覧と「自動選択」はその `meta` に保存され、同期で子プロバイダーを初めて作成するときの初期値になります。以降のエンドポイント設定は各子プロバイダー側のもので、同期が既存の子プロバイダーの設定を上書きすることはありません。

## 同期の仕組み

統合プロバイダーは **5 つのアプリすべて**（Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build）に同期されます。アプリごとのスイッチはありません：

- 統合プロバイダーを変更すると、5 つのアプリすべての設定が更新されます
- 統合プロバイダーを削除すると、5 つのアプリすべての設定も削除されます

生成される各アプリのプロバイダーはデータベース上 `universal-<app>-<id>` という名前で、各アプリのプロバイダー一覧に表示されます。以降は通常のプロバイダーと同じように扱えます（切り替え、編集、複製、削除）。

## 既存の統合プロバイダーの編集

専用の一覧ページはありません。統合プロバイダーが同期した子カードは **各アプリ** のプロバイダー一覧に表示されるので、任意のアプリ（例：Codex）でそのカードを開き、`⋯` メニューの **統合プロバイダーを編集** を選ぶと上記の共通設定を編集できます。別のアプリにある同じカードからも同じフォームが開きます。

## カスタム設定

各アプリの既存プロバイダーには、それぞれ充実したエディタ（上流フォーマット、モデルマッピング、思考能力、カスタム User-Agent、リクエスト上書き、完全な JSON / TOML エディタ）が残っています。一覧からプロバイダーを開き、「編集」をクリックしてください。

切り替え時に実際に設定ファイルへ書き込まれる内容と、グローバル設定とみなされる内容については、[2.3 プロバイダーの編集 → 設定エディタ](./2.3-edit.md#設定エディタ) を参照してください。

## 利用可能なモデル一覧

統合プロバイダーは **すべてのアプリで共通** のモデル一覧を 1 つ持ちます。各アプリのモデル欄のドロップダウンの選択肢はこれで決まり、各アプリのモデルカタログ（Codex の `/model` メニューなど）もここから生成されます。

1. **API Key** と **API アドレス** を入力します
2. 「利用可能なモデル」の **モデル一覧を取得** をクリックします
3. CC Switch はその資格情報で OpenAI 互換の `/v1/models` を呼び、[models.dev](https://models.dev) の公開データから **表示名** と **コンテキストウィンドウ** を補います（未知のモデルは ID のみ）
4. 取得した一覧は編集可能な表として表示されます。以降どのアプリからこのプロバイダーを開いても、ドロップダウンにはこのモデルだけが出ます

一覧は必要に応じて手入れできます：

| 操作 | 内容 |
|------|------|
| ID / 表示名 / コンテキストウィンドウを編集 | セルを直接編集します。ID を空にするとその行を削除します |
| 手動で追加 | 空行を追加します。ID を入れてください（表示名とウィンドウは任意） |
| 削除 | 各行のゴミ箱ボタン |
| 復元 | 手で編集したあと「最後に取得した内容に戻す」で取得時の状態に戻せます |

> 💡 各アプリの **モデルカタログはこの一覧から自動生成** されます（Codex の `/model` メニューと Grok Build のモデルテーブルがその例）。アプリごとに設定する必要はありません。段階が固定のアプリだけは個別に入力します — Claude Code のメインモデルと Sonnet / Opus / Fable / Haiku の 4 段階、Claude Desktop のロール表です。そこでは「段階」自体に意味があり、自由な一覧は対応付けられません。

`/v1/models` エンドポイントをサポートするプロバイダーで動作します。Codex OAuth 系プロバイダーは必要に応じて ChatGPT Codex バックエンドからリアルタイムのモデル一覧を取得します。

**よくあるエラー：**
- **認証失敗（401/403）**：API Key が正しいか確認してください
- **エンドポイント非対応（404/405）**：そのプロバイダーは `/v1/models` を公開していません。手動でモデル ID を入力してください
- **解析失敗**：レスポンスが OpenAI 互換形式ではありません
- **タイムアウト**：エンドポイントの応答が遅いです。しばらくして再試行するか、ネットワークを確認してください

## プロバイダーのインポート

CC Switch は 2 つの方法でプロバイダー設定をインポートできます：

### 方法 1：ディープリンクでインポート

`ccswitch://` プロトコルリンクでワンクリックインポート：

1. ディープリンクをクリックまたはアクセス
2. CC Switch が自動的に開き、インポート確認を表示
3. 設定情報をプレビュー
4. 「インポートを確認」をクリック

**ディープリンクの取得方法**：
- 他の人からの共有で取得
- [オンライン生成ツール](https://ccswitch.io/deplink.html) で作成

### 方法 2：データベースバックアップからインポート

SQL バックアップファイルから一括インポート：

1. 「設定 → データ」を開き、「データ管理」の「SQL インポート/エクスポート」を探す
2. 「SQL ファイルを選択」をクリック
3. 以前にエクスポートした `.sql` バックアップファイルを選択
4. 「インポート」をクリック
5. 既存の設定の上書きを確認

**インポート内容**：
- すべてのプロバイダー設定
- MCP サーバー設定
- Prompts プリセット
- 使用量ログ

> **注意**：インポートは既存のデータベースを上書きするため、事前に現在の設定をエクスポートしてバックアップすることをお勧めします。エクスポートファイル名の形式は `cc-switch-export-{タイムスタンプ}.sql` です。

## Codex OAuth リバースプロキシ（Claude プロバイダー）

CC Switch には **Codex OAuth リバースプロキシ** 経路があり、**ChatGPT アカウント** を使って Claude Code 内から Codex サービスを再利用できます。

> **位置ヒント**：この機能は **新しい Claude プロバイダーカードタイプ** として表示され、Codex 側のプリセットではありません。追加後は通常の API Key プロバイダーと並んで Claude のプロバイダーリストに表示されます。

### 前提条件

- ログイン可能な **ChatGPT アカウント**
- `auth.openai.com` および `chatgpt.com` にアクセスできる
- **利用前に必ず本節末尾の [⚠️ リスク通知](#️-リスク通知重要) をお読みください**

### 2 つの入口

以下のどちらの入口からでも開始できます：

#### 入口 A：プロバイダー追加ページから（新規ユーザー推奨）

1. **Claude** アプリに切り替える
2. ページヘッダーの **プロバイダーを追加** をクリック
3. Claude Code を有効にした統合プロバイダーを作成して保存する
4. 一覧から生成された Claude プロバイダーを開き、編集をクリック
5. まだ ChatGPT アカウントにログインしていない場合、フォームがログインフローへ誘導します（下記「ログインフロー」を参照）
6. ログイン成功後、フォームにログイン済みアカウントが表示されるので「保存」をクリックして完了

#### 入口 B：アカウントページから（マルチアカウント管理に適する）

1. サイドバーの **アカウント** をクリック
2. **ChatGPT** セクションで **アカウントを追加** をクリック
3. ログインフローを完了（下記参照）
4. ログイン完了後、**Claude** アプリに戻り、一覧からその Codex OAuth プロバイダーを開いて編集をクリック
5. フォーム内の「アカウントを選択」ドロップダウンから、先ほどログインしたアカウントを選択して保存

### ログインフロー（Device Code）

どちらの入口から入っても、ログインフローは同一です：

1. **認証コードを取得**：CC Switch が OpenAI Device Code フローを呼び出し、以下を表示：
   - **認証コード**（約 8 文字、例：`ABCD-1234`）
   - 認証コード右側の **コピー** ボタン
   - その下の認証 URL `https://auth.openai.com/codex/device`
   - 「認証を待機中...」のアニメーション表示
2. **ブラウザ認証**：リンクをクリック（または URL を手動で訪問）し、ブラウザで：
   - ChatGPT アカウントにログイン
   - 先ほどコピーした認証コードを入力
   - 認証を確認
3. **自動ポーリング完了**：CC Switch はバックグラウンドで OpenAI サーバーをポーリングし、認証成功を検知すると待機画面を自動的に閉じます
4. **ログイン済みアカウントを表示**：ログインした ChatGPT アカウントが **アカウント**ページの ChatGPT セクションに表示されます

> ⏱️ **認証コードの有効期限は約 15 分** です。タイムアウトすると、認証が完了しなかった旨が表示されます。ログインをやり直して新しい認証コードを取得してください。

### 有効化と使用

Codex OAuth プロバイダーを追加・保存した後：

1. カードに「ルーティングが必要」バッジが表示されます。まずアプリページ上部で「ルーティング」タブに切り替え、「ルーティングを開始」をクリックします（詳しくは[ローカルルーティング](../4-proxy/4.1-service.md)）
2. Claude のプロバイダーリストから探し、カードの「ここへ転送」をクリック —— その他の操作は通常のプロバイダーと同じ
3. Claude Code CLI がリバースプロキシ経由で ChatGPT のサブスクリプションを使用できるようになります
4. トレイメニューの **Claude** サブメニューにもこのプロバイダーが表示され、素早く切り替え可能

> **内部動作**：CC Switch はリクエストを `https://chatgpt.com/backend-api/codex` にルーティングし、base URL が強制的に書き換えられます —— フォームにエンドポイントを手動入力する **必要はありません**。API フォーマットは `openai_responses` に固定されます。

### デフォルトモデル

Codex OAuth プリセットのデフォルトモデルマッピング：

| 役割          | デフォルトモデル |
| ------------- | ---------------- |
| メインモデル  | `gpt-5.6-sol`    |
| Sonnet 役割   | `gpt-5.6-sol`    |
| Opus 役割     | `gpt-5.6-sol`    |
| Haiku 役割    | `gpt-5.6-luna`   |

プリセットは `CLAUDE_CODE_MAX_CONTEXT_TOKENS` と `CLAUDE_CODE_AUTO_COMPACT_WINDOW` も `372000` に設定し、ChatGPT Codex バックエンドのコンテキストウィンドウに合わせます。

Codex OAuth のモデル選択は固定リストだけに依存しません。モデルセレクターを開くと、CC Switch は必要に応じて ChatGPT Codex バックエンドから利用可能モデルを取得します。デフォルトマッピングは引き続き上書きできます。

プロバイダーの JSON エディタで `ANTHROPIC_MODEL` などの環境変数を上書きしてカスタマイズできます。

### マルチアカウント管理（アカウント）

**アカウント**ページでは、複数の ChatGPT アカウントを同時に管理できます（GitHub Copilot、xAI のアカウントもここにあります）：

| 操作                       | 説明                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| 別のアカウントを追加       | 「アカウントを追加」をクリックしてログインフローを繰り返す             |
| デフォルトに設定           | アカウント行のその他の操作から「デフォルトに設定」を選ぶ —— アカウントを指定していないプロバイダーはデフォルトのアカウントを使う |
| プロバイダー用に選択       | プロバイダーフォームの「アカウントを選択」ドロップダウンで特定アカウントを指定 |
| 再ログイン                 | アカウントに「再ログインが必要」と表示されたら、その他の操作から「再ログイン」を選ぶ |
| アカウントを削除           | アカウント行のその他の操作から「アカウントを削除」を選ぶ（Token がクリアされる） |
| すべてのアカウントを削除   | セクションのその他の操作から「すべてのアカウントを削除」を選ぶ         |

> **使用シーン**：チームで開発マシンを共有する場合、各メンバーの ChatGPT アカウントごとに 1 つのプロバイダーを作成し、トレイメニューから素早く切り替えできます。

### Token 自動更新

- Token は **有効期限の 60 秒前** に自動更新され、すべてバックグラウンドで処理されるため手動介入は不要です
- Refresh Token はローカルデータディレクトリに保存され、どこにもアップロードされません
- Token のエクスポートは **サポートされていません**（漏洩防止）

### クォータ表示

ログインすると、**アカウント**ページのアカウント行の右側に、そのアカウントのクォータバー（「残り」で表示）と「x 分前」の更新時刻が表示されます。更新アイコンをクリックすると手動で再取得できます。

> ⚠️ **再ログインが必要**：Token が完全に無効になった（自動更新できない）場合、アカウント行に「再ログインが必要」と表示されます。**アカウント**ページでそのアカウントの「再ログイン」を選ぶか、削除して追加し直してください。

### よくある失敗

| シナリオ                    | 表示                              | 解決方法                                      |
| --------------------------- | --------------------------------- | --------------------------------------------- |
| 認証コードのタイムアウト    | ログインが完了しなかった旨のメッセージ | ログインをやり直し、新しい認証コードを取得 |
| ブラウザで認証拒否          | ログインが完了しなかった旨のメッセージ | 再ログインし、ブラウザで「認証」をクリック |
| ネットワークエラー          | 具体的なエラー情報を表示          | ネットワーク接続を確認、OpenAI ドメインへのアクセス可否を確認 |
| ログイン前にプロバイダー追加 | 「先に ChatGPT にログインしてください」 | 先にアカウントページでログインを完了 |
| Token 更新失敗              | アカウント行に「再ログインが必要」 | そのアカウントで再ログイン |
| クォータ取得失敗            | アカウント行に「残量を取得できません」 | 更新アイコンをクリックして再試行 |

### ⚠️ リスク通知（重要）

Codex OAuth リバースプロキシは **リバースエンジニアリングされた OAuth フロー** で ChatGPT アカウントの Codex サービスにアクセスします。有効化前に必ず以下のリスクをご理解ください：

1. **利用規約違反**：OpenAI の利用規約に違反する可能性があります。同規約は未承認の自動化アクセス、サービスの複製、および既定のアクセス経路の迂回を禁止しています
2. **アカウントリスク**：OpenAI は異常な使用パターンを疑わしい自動化として検知し、ChatGPT アカウントに一時的または永続的な制限を課す可能性があります
3. **長期的な可用性は保証されません**：OpenAI は認証および検出メカニズムをいつでも更新する可能性があり、現在利用可能な方法が将来ブロックされる可能性があります

**この機能を有効化することは、すべてのリスクを自己責任で負うことを意味します**。CC Switch は本機能の使用による一切のアカウント制限、警告、サービス停止について責任を負いません。

> 📖 完全な免責事項と背景は [v3.13.0 Release Notes](../../../release-notes/v3.13.0-ja.md#️-リスクに関する注意事項) をご覧ください。

## 高度なオプション

### 上流フォーマット（Claude）

サードパーティ API を使用する Claude プロバイダーを追加する際、高度なオプションセクションで正しい **上流フォーマット** を選択する必要がある場合があります：

| フォーマット | 説明 | 使用場面 |
|------|------|------|
| **Anthropic Messages（ネイティブ）** | ネイティブ Anthropic API フォーマット（デフォルト）。直接接続し、変換しない | Anthropic API に直接接続、または互換プロキシ |
| **OpenAI Chat Completions（ルーティングが必要）** | ローカルルーティングが変換 | プロバイダーが OpenAI Chat フォーマットのみ対応 |
| **OpenAI Responses API（ルーティングが必要）** | ローカルルーティングが変換 | プロバイダーが OpenAI Responses フォーマットのみ対応 |
| **Gemini Native generateContent（ルーティングが必要）** | ローカルルーティングが変換 | プロバイダーが Gemini ネイティブインターフェースのみ提供 |

> **注意**：フォーマット変換はローカルルーティングが担当します。Anthropic 以外のフォーマットを使用する場合、リクエスト/レスポンスを正しく変換するには、ローカルルーティングを有効にし、Claude のルーティングを有効にする必要があります。詳しくは [4.1 ローカルルーティングサービス](../4-proxy/4.1-service.md) をご覧ください。Codex と Grok Build の上流フォーマットについては後述します。

デフォルト以外の API フォーマットが設定されている場合、高度なオプションセクションが自動展開されます。

### 完全URLエンドポイントモード

デフォルトでは、CC Switch は設定された `base_url` を **プレフィックス** として扱い、`/v1/chat/completions` などの固定パスを後ろに連結します。一部のベンダー（非標準の URL レイアウトを必要とする第三者サービスなど）では、この連結方式ではリクエストが失敗します。

**有効化方法**：

1. プロバイダーを編集し、API エンドポイント欄の横にある **フル URL** スイッチをオンにする
2. **完全なアップストリームエンドポイント**（プレフィックスではなく）を API エンドポイント欄に入力

> ⚠️ **完全 URL モードはローカルルーティングと組み合わせて使用する必要があります**：ローカルルーティングがこの URL をそのまま使用し、パスを連結しません。有効にすると、プロバイダーカードに「ルーティングが必要」と表示され、切り替え時にも先にルーティングを起動するよう案内されます。

**例の比較**：

| モード                  | `base_url` の記入例                               | 実際のリクエスト先                                |
| ----------------------- | ------------------------------------------------ | ------------------------------------------------ |
| デフォルト（プレフィックス連結） | `https://api.example.com`                      | `https://api.example.com/v1/chat/completions`    |
| **完全 URL モード**     | `https://api.example.com/custom/path/messages`   | `https://api.example.com/custom/path/messages`   |

**使用シーン**：
- ベンダーが非標準パスを要求する場合（`/v1/chat/completions` 以外）
- ベンダーに多階層のパス構造がある場合
- ベンダー専用の API ゲートウェイパス

> 💡 **ヒント**：このオプションを無効にすると、パス連結はデフォルトの動作に戻り、このプロバイダーも完全 URL を理由にローカルルーティングを必要としなくなります。

### Claude クイックトグル

Claude プロバイダーの追加・編集時、JSON エディタの上部に **クイックトグル** が利用できます：

| トグル | 効果 | 設定変更 | 適用範囲 |
|------|------|------|------|
| **AI署名を非表示** | コミット/PR の帰属メタデータとセッションリンクをクリア | `attribution: {commit: "", pr: "", sessionUrl: false}` を設定 | グローバル |
| **Tool Search を有効化** | ツール検索機能を有効化 | `env.ENABLE_TOOL_SEARCH = "true"` を設定 | プロバイダーごと |
| **自動アップグレードを無効化** | Claude Code の自動更新を防止 | `env.DISABLE_AUTOUPDATER = "1"` を設定 | グローバル |
| **Artifact ツールを無効化** | Artifact ツールをリクエストの tools 配列に含めない（一部のサードパーティゲートウェイはそのスキーマ検証に失敗し、すべてのリクエストで 400 を返す） | `env.CLAUDE_CODE_DISABLE_ARTIFACT = "1"` を設定 | プロバイダーごと |
| **auto mode のサーバー側チェックを無効化** | auto mode が最初からローカルチェックを使うようにする。ゲートウェイはサーバー側チェックに対応していないため、オフのままだとセッションごとに一度「対象外」の通知で止まり、Enter を押してからローカルチェックに切り替わる。サードパーティのプロバイダーを新規追加するときは既定でオン。公式エンドポイントではオンにしない | `env.CLAUDE_CODE_AUTO_MODE_SERVER = "0"` を設定 | プロバイダーごと |

トグルのチェックを外すと、対応する設定エントリが完全に削除されます。変更は JSON エディタにリアルタイムで反映されます。

- **グローバル**：保存すると `~/.claude/settings.json` に書き込まれ、すべてのプロバイダーに適用されます。どのプロバイダーで変更しても同じです。
- **プロバイダーごと**：このプロバイダーに保存され、このプロバイダーに切り替えたときに設定ファイルに書き込まれ、別のプロバイダーに切り替えると削除されます。この 3 項目への対応はサードパーティのエンドポイントによって異なるため、プロバイダーごとに設定します。

エディタのその他の内容の保存ルールは [2.3 プロバイダーの編集 → 設定エディタ](./2.3-edit.md#設定エディタ) を参照してください。

### Codex / Grok Build の上流フォーマットとモデルマッピング

Codex はネイティブでは OpenAI Responses API を使用します。Grok Build は Codex と同じ Responses パイプラインを共有しているため、以下の「上流フォーマット」と「思考能力」は Grok Build にも当てはまります。「モデルマッピング」は Codex のみが対象です。

#### 上流フォーマット

Codex または Grok Build のプロバイダーを編集する際、高度なオプションの **上流フォーマット** によって、CC Switch が上流とどのように接続するかが決まります：

| オプション | 説明 |
|------|------|
| **Responses（ネイティブ）** | 上流がネイティブで Responses API に対応。直接接続し、フォーマットを変換しない |
| **Chat Completions（ルーティング必須）** | 上流が Chat Completions のみを提供。ローカルルーティングが Responses リクエストを Chat Completions に変換し、レスポンス（ストリーミング SSE、推論内容、ツール呼び出しを含む）を Responses に変換し直す |
| **Anthropic Messages（ルーティング必須）** | 上流が Anthropic Messages のみを提供。ローカルルーティングが変換する |

後の 2 つを選択した場合は、[ローカルルーティングサービス](../4-proxy/4.1-service.md)を有効にし、該当アプリのルーティングを有効にする必要があります。使用中はローカルルーティングを起動したままにしてください。上流フォーマットは選択したプロトコルに従います。変更が必要な場合は高度なオプションで調整してください。

#### モデルマッピング（Codex のみ）

Codex の非公式プロバイダーのフォームには、すべて **モデルマッピング** 表があり、このプロバイダーで利用可能なモデルを宣言できます：

| 列 | 説明 |
|------|------|
| メニュー表示名 | `/model` コマンドに表示される名称 |
| 実際のリクエストモデル | 上流の実際のモデル名（例：`deepseek-v4-flash`） |
| コンテキストウィンドウ | （任意）モデルのコンテキスト長 |
| 思考レベル | （任意）このモデルが対応する思考レベル |

- マッピング表は Codex の `model_catalog_json` を生成し、`/model` コマンドでこれらの第三者モデル名を表示できるようにします
- 表のエントリーは入力内容のまま保存され、モデルリストの唯一の情報源となります
- **デフォルトモデル** を空欄にすると、マッピング表の 1 行目がデフォルトで使用されます
- 変更後、モデルリストを更新するには **Codex の再起動が必要** です（`model_catalog_json` は Codex 起動時に読み込まれます）

#### 思考能力（Reasoning）

上流フォーマットが Chat Completions の場合、ローカルルーティングは Codex が送る思考リクエストを上流が理解できるパラメータに変換します。高度なオプションの **思考能力** グループには 2 つのスイッチがあります：

| スイッチ | 意味 |
|------|------|
| **思考モードに対応** | 上流が thinking のオン / オフに対応（Kimi、GLM、Qwen などは通常こちら） |
| **思考レベルに対応** | 上流が low / high / max などの思考深度の制御に対応。有効にすると思考モードも自動的に有効になり、Codex の `reasoning.effort` を上流のパラメータに変換する |

この 2 つのスイッチは名前・アドレス・モデル名から自動的に推定されるため、判定が正しくない場合にのみ手動で調整してください。

> ⚠️ **一部のプロバイダーでは思考レベルが効きません**：プロバイダーが「思考モード」にしか対応していない場合、Codex で思考レベル（`model_reasoning_effort`）を変えても**効果はありません**——CC Switch はこれらの上流にレベルを送りません（API がパラメータを受け付けず、無理に送るとリクエストが拒否される可能性があるため）。

上流フォーマットが Responses（ネイティブ）の場合、思考パラメータは Codex からそのまま送信され、この変換は行われません。

### Codex 1M コンテキストウィンドウ

Codex プロバイダーの追加時、**1M コンテキストウィンドウ** トグルが利用できます：

- **有効時**：config.toml に `model_context_window = 1000000` を設定し、`model_auto_compact_token_limit = 900000` を自動入力
- **無効時**：両方のフィールドを削除

トグルがオンの場合に表示されるテキストフィールドで、自動コンパクト制限をカスタマイズできます。このトグルは Codex プロバイダーの新規追加時のみ表示されます。既存プロバイダーの編集時は、必要に応じて高度な設定で該当フィールドを直接調整してください。

### カスタムアイコン

名前の左にあるアイコンをクリックするとアイコン選択画面が開きます。内蔵アイコンを選ぶほか、自分の画像（PNG、JPG、WebP、SVG、2 MB まで）をアップロードして「マイアイコン」に保存でき、ほかのプロバイダーでもそのまま選べます。詳しくは [2.3 プロバイダーの編集 → アイコンのカスタマイズ](./2.3-edit.md#アイコンのカスタマイズ) を参照してください。

### Web サイトリンク

プロバイダーの公式サイトやコンソールのアドレスを入力して、素早くアクセスできます：

- プロバイダーカードのリンクアイコンをクリックすると直接開く
- 残額の確認や API Key の取得などに使用

### メモ

以下のようなメモ情報を追加できます：

- アカウントの用途（個人/仕事）
- プランの情報
- 有効期限

メモはプロバイダーカードに表示され、検索にも対応しています。

### エンドポイント速度テスト

プロバイダーの追加や編集時に、API エンドポイントの速度テストができます：

1. プロバイダーを編集し、リクエスト先アドレスの横にある「管理・テスト」をクリック
2. テストパネルで複数のエンドポイント URL を追加
3. 「テスト」をクリックして実行
4. レイテンシが最も低いエンドポイントを選択

**テスト結果**：
- 🟢 緑：レイテンシ < 300ms
- 🟡 黄：レイテンシ 300–500ms
- 🟠 オレンジ：レイテンシ 500–800ms
- 🔴 赤：レイテンシ ≥ 800ms
